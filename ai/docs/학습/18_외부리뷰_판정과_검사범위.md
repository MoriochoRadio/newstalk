# 18. 외부 리뷰를 판정하는 법, 그리고 "검사 범위" 버그 (2026-11-17)

## 리뷰 지적 = 가설

리뷰는 "이게 버그 같다"는 가설일 뿐입니다. 코드를 열어 넷 중 하나로 나눕니다.

1. **진짜 버그**: 고친다 + 고치기 전엔 실패하는 시험을 남긴다
2. **의도된 설계**: 주석·결정사항에 이유가 이미 있음 (예: 실패해도 10분 쿨다운 = 연타 방지)
3. **사실이지만 영향 작음**: 기록만 (예: 캐시 dict 경합 → 최악이 캐시 미스)
4. **알려진 한계**: 이미 문서에 적힘

## 버그: LLM 이 본 글 ≠ 검사한 글

요약 검사(`check`)는 "LLM 답의 숫자가 기사에 있나"를 봅니다. 그런데

- LLM 에 보낸 글: 관련종목 줄을 **지운 뒤** 앞 3,000자
- 검사에 쓴 글: **원문** 앞 3,000자

관련종목 줄이 길면 두 범위가 어긋나서, LLM 이 실제로 읽고 쓴 숫자를 "기사에 없음"으로 거부했습니다.

```python
# 전
text_ = title + "\n" + body[:MAX_CHARS]
# 후: LLM 에 보낸 것과 똑같이 자름
text_ = title + "\n" + article_text(body)[:MAX_CHARS]
```

교훈: **입력을 가공하는 곳이 두 군데면 같은 함수를 써야 한다.** 따로 쓰면 언젠가 어긋납니다.

## 시험이 진짜 버그를 잡는지 확인하는 법

새 시험을 넣고 → 고치기 전 코드로 돌려 **실패하는지** 봅니다 (`git stash` 로 잠깐 되돌림). 고친 뒤에는 통과해야 합니다. 둘 다 통과하면 그 시험은 아무것도 안 지키는 것입니다.
