# 13. LLM 답 검사 (`step5_summary.check`, 2026-11-11)

## 한 줄 요약

LLM 이 준 답을 저장하기 전에 **코드로 한 번 더 검사**한다. 기사에 없는 숫자면 거부하고, 감성 이유가 "주가가 올랐다"뿐이면 긍정·부정을 중립이나 판단 보류로 바꾼다.

## 왜 필요한가

프롬프트에 규칙을 적어도 LLM 은 가끔 어긴다. 시험지에 "답은 연필로" 라고 적어 놔도 볼펜으로 쓰는 사람이 있는 것과 같아서, 걷어 간 뒤에 한 번 더 봐야 한다.

실제 사례 (기사 12021, "삼성전자 20만원·SK하이닉스 123만원 회복…반도체주 급등"):
- 프롬프트 규칙: "주가 급등락 기사는 원인 사실로 판단하고, 원인이 없으면 NEUTRAL"
- LLM 답: 감성 `POSITIVE`, 이유 "전 거래일 대비 주가가 8.71% 상승해 주가 레벨이 회복됐다."
- 주가가 올랐다는 건 이미 일어난 일이라 좋은 소식의 **원인**이 아니다. 기준은 [라벨 기준 v2.1](../평가/라벨_기준_v2.md) 3절의 규칙 5 와 규칙 2

## 들어가고 나오는 것

| | 내용 |
|---|---|
| 들어감 | LLM 답(`ArticleSummary`), 기사 제목, 본문 |
| 나옴 | 고친 답. 숫자·연도가 틀리면 `ValueError` → 그 기사만 재시도 |
| 비용 | 0 (코드만 돎, LLM 을 다시 부르는 건 재시도할 때뿐) |

## 코드 따라 읽기

**① 없는 숫자 거부** (`check` 안)
```python
wrong = unknown_numbers(s.summary, text_)
if wrong:
    raise ValueError(f"기사에 없는 숫자: {wrong}")
```
`unknown_numbers` 는 [10번 문서](10_종목별_하루요약.md)의 하루 요약에서 쓰던 함수다. 글자가 아니라 **값**으로 비교해서, 기사의 "9조4천억원" 을 요약에 "9.4조원" 으로 써도 통과한다.

**② 주가 움직임뿐인가** (`price_only`)
```python
def price_only(reason):
    return bool(PRICE_MOVE.search(reason)) and not CAUSE.search(reason)
```
두 낱말 목록으로 본다.
- `PRICE_MOVE`: 주가가 움직였다는 표현이 있나 ("주가가 … 상승", "12.97% 하락", "하락 폭")
- `CAUSE`: 원인이 되는 사실이 있나 (실적, 계약, 임상, 공개매수, 유가, 규제 …)
- 움직임은 있는데 원인 낱말이 **하나도 없을 때만** 걸린다. 원인이 하나라도 있으면 LLM 판단을 그대로 둔다 (맞는 판단을 잘못 끄는 것보다 놓치는 쪽이 낫다고 봄)

**③ 감성 바꾸기** (`check` 안)
```python
for c in s.companies:
    if c.sentiment in ("POSITIVE", "NEGATIVE") and price_only(c.reason):
        c.sentiment = "UNCERTAIN" if SPECULATIVE.search(c.reason) else "NEUTRAL"
```
- 원인이 아예 없으면 → `NEUTRAL` 중립 ("판단했더니 영향 없음")
- 원인이 우려·기대·가능성뿐이면 → `UNCERTAIN` 판단 보류 ("판단할 근거가 모자람"). 6단계에서 `NULL` 로 저장돼 감성 비율에서 빠진다

## 왜 공시에는 숫자 검사를 안 쓰나

처음엔 공시 요약에도 넣었는데, 최근 공시 10건 중 3건을 **맞는 요약인데** 거부했다.

| 공시 원문 | LLM 요약 | 왜 걸렸나 |
|---|---|---|
| 표 머리 "단위 : 백만원", 칸에 `24,529` | 24,529백만원 | 단위가 표 머리에 따로 있음 |
| `2026-07-01` | 2026.07.01 | 날짜 쓰는 방식이 다름 |
| `29,120,699,771` 원 | 291억 | 반올림 |

**규칙을 넣고 나서 실제 데이터에 대 보는 이유**가 이것이다. 시험을 통과해도 실제 자료에서는 틀릴 수 있다.

## 한계

- 낱말 목록 규칙이라 목록에 없는 원인이 나오면 잘못 바꿀 수 있다
- 새로 요약하는 기사부터 적용된다. 지난 데이터는 그대로다
- 지난 답 980개(긍정·부정)에 대 보면 45개가 바뀐다 (중립 37, 판단 보류 8). 정답지로 정확도를 다시 재지는 못했다 (정답지가 백엔드1 PC 에만 있음)

## 직접 해보기

비용 없음, DB 없어도 됨. `python` 을 켜고:
```python
from hk_llm.steps.step5_summary import price_only, SPECULATIVE
from hk_llm.steps.step8_daily import unknown_numbers

price_only("전 거래일 대비 주가가 8.71% 상승해 주가 레벨이 회복됐다.")   # True
price_only("3분기 영업이익이 전망치를 밑돌아 주가가 급락했다.")          # False (원인이 있음)
price_only("수익성 우려가 커지며 주가가 하락했다.")                     # True
bool(SPECULATIVE.search("수익성 우려가 커지며 주가가 하락했다."))       # True → 판단 보류

unknown_numbers("영업이익 12조원", "영업이익 9조4천억원")     # ['12조'] → 거부
unknown_numbers("영업이익 9.4조원", "영업이익 9조4천억원")    # [] → 통과
```

## 확인 질문

**Q1.** 프롬프트에 규칙이 있는데 왜 코드로 또 검사하나?
<details><summary>▶ 답 보기</summary>

LLM 은 규칙을 가끔 어긴다. 지난 답 980개 중 45개가 "주가가 올랐다"뿐인 이유로 긍정·부정을 줬다. 코드 검사는 매번 똑같이 돌고 비용도 들지 않는다.
</details>

**Q2.** "실적 부진으로 주가가 급락했다" 는 왜 안 바뀌나?
<details><summary>▶ 답 보기</summary>

`실적` 이 `CAUSE` 목록에 있어서 `price_only` 가 False 다. 원인 사실이 있으면 그 사실로 판단한 것이라 LLM 답을 그대로 둔다.
</details>

**Q3.** 중립과 판단 보류는 뭐가 다른가?
<details><summary>▶ 답 보기</summary>

중립은 "판단했더니 영향이 없다", 판단 보류는 "판단할 근거가 모자란다" 이다. 판단 보류는 DB 에 `NULL` 로 저장되어 감성 비율 계산에서 빠진다.
</details>

**Q4.** 숫자 검사를 왜 공시에는 안 쓰나?
<details><summary>▶ 답 보기</summary>

공시 숫자는 표에 있어서 단위가 표 머리에 따로 있고, LLM 이 날짜 형식을 바꾸거나 반올림해 쓴다. 값을 그대로 맞추는 검사로는 맞는 요약까지 거부했다 (10건 중 3건).
</details>
