# 17. 화면 파일 나누기(V8)와 CSS 변수 (2026-11-16)

**한 줄 요약:** 1,992줄짜리 화면 파일을 "기능별 훅 + 작은 컴포넌트"로 나누고, 다크 모드를 `!important` 대신 CSS 변수로 칠했다. 화면은 한 픽셀도 안 바뀌었다는 걸 브라우저에서 확인했다.

## 왜 필요했나

외부 채점에서 프론트가 가장 낮은 점수(2.5)를 받았다.

- `DashboardPageV7.jsx` 하나에 `useState` 47개, `useEffect` 23개. 검색을 고치려 해도 글 목록·로그인·관심 종목 코드가 다 섞여 있어 어디가 어디에 영향을 주는지 알기 어려움
- CSS 의 `!important` 51개. `!important` 는 "무조건 이 값"이라서, 나중에 더 구체적인 규칙을 써도 안 먹힘 → 또 `!important` 를 붙이는 악순환
- 다크 모드가 색을 변수로 바꾸는 대신 선택자마다 색을 직접 다시 적음 (색 213곳)

## 코드 따라 읽기

**1) 같은 코드를 하나로 — `useQuoteFetch`**

V7 은 "현재가 여러 개 받아서 합치기"를 세 군데에서 거의 똑같이 했다. 지금은:

```js
useQuoteFetch(codesKey, addQuotes);   // codesKey = "005930,000660"
```

종목 목록을 **문자열 하나**로 넘기는 게 요점이다. 배열은 렌더링마다 새로 만들어져 매번 "바뀌었다"고 판단되지만, 문자열은 내용이 같으면 같다 → 쓸데없이 다시 부르지 않는다.

**2) 상태를 쓰는 곳 안으로 — `SearchBox`**

검색어·기간·자동완성 열림은 검색창만 쓴다. 그런데 V7 은 이걸 맨 위 화면이 들고 있어서, 글자 하나 칠 때마다 대시보드 전체가 다시 그려졌다. 쓰는 컴포넌트 안으로 옮기면 그 컴포넌트만 다시 그린다.

**3) `!important` 없애기**

`!important` 를 지우면 "원래 이기던 규칙"이 지는지가 문제다. 규칙이 이기는 순서는 **구체성**(id > class > 태그)이고, 같으면 **뒤에 쓴 것**이 이긴다.
- `.app-shell.dark-mode .pagination-bar` (클래스 3개) 는 `.pagination-bar` (1개) 를 이미 이긴다 → `!important` 가 원래 필요 없었음
- 지웠더니 살아나는 규칙이 하나 있었다: `.quick-chip.active .quick-chip-rate.up` (선택된 칩의 등락률 색). 지금까지 `!important` 에 눌려 한 번도 적용된 적이 없었음 → 화면을 그대로 두려고 이 규칙을 지움

**4) 다크 모드를 변수로**

```css
:root                { --line-soft: #e2e8f0; }   /* 밝은 모드 */
.app-shell.dark-mode { --line-soft: #2d3748; }   /* 다크 모드 */
.empty-state { border: 1px dashed var(--line-soft); }  /* 규칙은 한 번만 */
```

규칙은 한 번만 쓰고, 다크 모드는 변수 값만 바꾼다. 다크 규칙 안에 적힌 `#2d3748` 같은 색은 같은 값의 변수로 바꿨고(138곳), 밝은 모드와 같아진 다크 덮어쓰기는 지웠다(31개).

## 화면이 안 바뀌었다는 걸 어떻게 아나

눈으로 보는 건 놓친다. 브라우저에서 화면의 **모든 요소**에 대해 `getComputedStyle`(브라우저가 최종 계산한 색·여백·배치)을 44개 속성씩 저장해 두고, 고친 뒤 다시 재서 비교했다.

- 화면 11개(홈, 판단 방법 창, 로그인 창, 검색 자동완성, 종목 4개 탭, 관심 종목 관리 창, 종목 탐색, 관심 종목) × 밝은/다크 = 22장면
- 고치기 전에 같은 코드로 두 번 재서 차이 0인 것부터 확인 (재는 방법 자체가 흔들리지 않는지)
- 함정 1: 앱 창 크기가 바뀌어 화면 배율이 1.25 → 1.0 이 되자 테두리가 0.8px → 1px 로 전부 달라 보임 → 0.5px 이하 차이는 같은 값으로 봄
- 함정 2: 5분마다 새 기사가 모여 목록 구성이 바뀜 → "요소가 생김/사라짐"은 데이터, "같은 요소의 스타일이 다름"만 코드 문제로 봄
- 못 재는 것: 마우스를 올렸을 때(`:hover`), 버튼이 꺼졌을 때(`:disabled`) → 이건 구체성을 계산하는 스크립트로 따로 확인

## 확인 질문

1. `useQuoteFetch` 에 종목 배열 대신 `"005930,000660"` 같은 문자열을 넘기는 이유는?
   <details><summary>▶ 답 보기</summary>배열은 렌더링마다 새로 만들어져 React 가 "바뀌었다"고 보고 효과를 다시 실행한다. 문자열은 내용이 같으면 같은 값이라 목록이 실제로 바뀔 때만 다시 받는다.</details>
2. `!important` 를 지웠을 때 화면이 바뀔 수 있는 경우는?
   <details><summary>▶ 답 보기</summary>그 요소에 같은 속성을 정하는 다른 규칙이 있고, 그 규칙이 구체성이 더 높거나(같으면 더 뒤에 있으면) 그동안 눌려 있던 그 규칙이 살아난다. 이번엔 선택된 빠른 전환 칩의 등락률 색이 그랬다.</details>
3. 다크 모드 덮어쓰기를 지울 때 "밝은 모드 규칙과 값이 같다"만으로 충분하지 않은 이유는?
   <details><summary>▶ 답 보기</summary>다크 규칙은 구체성이 높아서, 그 사이에 있는 다른 밝은 모드 규칙까지 눌러 왔을 수 있다. 지우면 그 중간 규칙이 이겨서 값이 바뀐다. 그래서 사이에 끼어드는 규칙이 없는 것만 지웠다.</details>
