## 3. 처리 흐름 (RSS 실시간) ✅

```
RSS 목록 → 중복 제거 → 본문 수집 → LLM 요약 → 요약에서 종목 매칭 → 완료
              │            ├ 실패 시 3번 재시도 후 버림
              │            └ 본문이 없는 기사(유료·[속보]·[표])는 재시도 없이 SKIPPED (2026-11-02)
              └ robots 금지 기사는 처음부터 제외 (robots 확인 실패는 금지가 아니라서 LISTED 로 두고 다음 실행에 다시)
요약 후 연결된 종목이 없으면 버림 ✅
종목 매칭은 match_setting 점수 방식 사용 (23번에서 적용) ✅
매칭 점수: 이름이 맞으면 기본 통과(주인공 1.00, 조연 0.83), 테마가 맞으면 점수만 올림, 안 맞아도 안 깎음 🧪 (2026-11-02, 원래 공식과 달라 팀 공유 필요)
OpenAI 월 예산 50,000원 ✅
요약 모델 gpt-5.4-nano, 날짜 고정 버전 gpt-5.4-nano-2026-03-17 (2026-11-06) (기사 1건 약 $0.0006 실측. 하루 1,000건 월 약 $19, 최대 추정 1,600건 월 약 $30) ✅
주제 확인: 시황·전망·지표 기사와 명단 기사(본문 종목 5개 초과, 제목에 주인공이 있으면 10개 이상)는 연결 안 함, 그 밖에는 주인공·조연 모두 제목이나 본문 앞 200자에 이름이 있거나, 본문에 2번 이상 나와야 연결 🧪 (2026-11-03, 백엔드1 개선 반영)
LLM 이 뽑은 회사 목록은 article.companies 에 보관 → 매칭은 그걸로 (LLM 다시 안 부름). 백엔드 V7 ✅
종목별 하루 요약: 기사 1건은 LLM 없이, 2건 이상만 합침 (주인공·관련도 높은 순 10건), 공시 제외 (32번). 답의 연도·두 자리 이상 숫자가 자료에 없으면 기존 요약 유지, 새 기사가 올 때까지 다시 안 부름 🧪 (2026-11-04)
자동 실행(35번): python -m hk_llm.loop 또는 Docker 프로필 ai. 5분마다, 하루 요약은 1시간마다, SNS 는 SNS_ENABLED=true 일 때만 별도 스레드·잠금으로 1시간마다 (기본 꺼짐, 2026-11-09). 본문·요약·공시 모두 어제 이후만, 새 기사부터. 코드 완성, 켜는 시점은 사용자 결정 ✅ (2026-11-03)
AI 서버: FastAPI 사용 (hk_llm/api.py). 수집은 서버와 별도 프로세스. 내부 토큰 필수, 같은 종목은 10분에 1번. 백엔드 POST /api/stocks/{code}/summary 가 호출 (PR #49) ✅ (2026-11-04)
역할: 뉴스 수집·종목 매칭·요약 개선과 백엔드 통합은 백엔드1, SNS 수집은 지승현 ✅ (팀 합의, docs/decisions.md 2026-11-03)
SNS 카페 글: 응답에 날짜가 없어 카페별 글 번호로 새 글 판단. 처음 보는 카페와 작은 번호는 SKIPPED. SNS summary 는 원문 미리보기라 model·summarized_at 을 비움 🧪 (2026-11-04)
간접 연결(회사 이름 없는 기사): 1차 서비스에 안 넣음. 독립 정답지 Precision 16.7% ✅ (docs/decisions.md 2026-11-04)
관련도(relevance)는 연결 여부와 별개로 계산: 제목 0.40 또는 첫 부분 0.20 + 주인공 0.25 + 언급 횟수 최대 0.25 + 테마 0.10. 근거 문장(evidence)은 코드로 고름 🧪 (백엔드1)
LLM 비용: 호출마다 토큰을 logs/llm_usage.json 에 기록, 하루 상한 $2 (LLM_DAILY_USD, 추정치 기준). 넘으면 그날 요약을 멈추고 수집·연결은 계속 🧪 (2026-11-04)
SNS 글: 모은 지 7일 뒤 행 삭제 (네이버 약관 7.3, docs/decisions.md). 하루 요약은 남음. 일반 단어 종목명 9개 제외 (손으로 고름). 광고·연락처는 is_spam 으로 글과 LLM 답을 같이 검사 🧪 (2026-11-04)
```

- 버린 기사도 DB 에 **줄은 남기고 상태만 표시** → 같은 기사를 다시 받아 다시 요약하는 낭비 방지. 예외: SNS 글은 7일 뒤 지움
- 네이버 API 쪽(⏸)은 반대로 매칭 → 요약 (검색어가 종목명이라 이미 매칭된 상태)

| 언론사 이름 | 주요 언론사만 도메인→이름 표, 없으면 도메인 그대로 |

| RSS 짧은 요약문 | 저장 |
| 본문 | 정제해서 저장, **7일 후 삭제** |
| LLM 요약 | **계속 보관**. SNS 글의 `summary` 는 원문 미리보기라 글과 함께 7일 뒤 지움 |
| 시간 | 전부 **KST**. 발행 시각 없으면 수집 시각으로 채움 |

## 5. DB

- ✅ **DB 실행 방식: 팀 공용 Docker MariaDB** 11.8.9 (`stocknews`, 포트 3308, 앱 전용 계정, root 금지) (2026-11-02). 팀 `docs/decisions.md` 2026-10-30 AI 테이블(V5) 항목과 같음
- ✅ **테이블은 백엔드가 Flyway 로 생성** (팀 규칙) → AI 는 컬럼 제안서만: [AI테이블_제안.md](AI테이블_제안.md)

| 테이블 | 내용 |
|---|---|
| `article` | 기사 1건 = 1줄. 주소·언론사·제목·기자·요약문·본문·시각·상태·LLM 요약·회사 목록(`companies`, V7) |
| `article_stock` | 기사 1건 : 종목 N개. 종목코드·대표 종목 여부·감성(NULL 허용, V12)·이유·근거 문장·사실 종류(`fact_type`, V14)·같은 소식 묶음(`group_article_id`, V13) |
| `collect_run` | 실행 1번 = 1줄. 시작·끝·성공 여부·건수 → 화면의 "갱신 시각" |
| `stock_daily_summary` | 종목·날짜마다 1줄. 뉴스 종합 요약 (SNS 여론 요약 `sns_summary` 는 SNS 를 1차에서 빼서 안 채움) (감성 비율 화면은 백엔드가 직접 셈) |

- 처리 상태: `LISTED` → `FETCHED` → `SUMMARIZED` → `DONE` / 버림: `FAILED`, `SKIPPED`, `NO_STOCK`
- 종목 정보·별칭·테마·점수 설정은 백엔드 테이블(`stock_info`, `stock_alias`, `stock_theme`, `match_setting`) 을 읽음

## 6. 백엔드·프론트와 주고받는 방식 🧪

화면용 데이터 예시는 [팀공유.md](팀공유.md)

| AI 생성 표시 | 요약마다 모델명·요약 시각 저장, 문구는 프론트 |

## AI 활용 금지 언론사는 제목만 연결 ✅ (2026-11-05, 백엔드1 · AI 파트 권한 합의)

- **결정:** 기사 끝에 "AI 학습 및 활용 금지"를 적은 연합뉴스·서울경제·연합인포맥스는 본문을 받지 않고 LLM 에도 넣지 않음. 제목을 낱말로 잘라 종목 사전과 **정확히 맞는 이름만** 연결(조사 하나는 떼고 봄), 감성은 판단하지 않음(`article_stock.sentiment = NULL`, 백엔드 V12). 예전에 만든 본문·요약·LLM 답은 지움
- **제목 규칙:** 부분 일치 안 함(태양광→태양, RISK→SK 방지), 헷갈리는 별칭과 같은 이름·두 글자 그룹 지주사(SK·LG·한화…)·일반 낱말 종목명(대상·상보·미래산업 등) 제외, 종목 4개 이상이면 명단 제목, 다른 회사에 대한 증권사 의견이면 증권사는 출처로 보고 뺌
- **측정 (정답지, Claude 라벨 기준):** 금지 언론사 41건에서 제목만 연결 P 96.7% (29/30, 95% CI 83.3~99.4%), R 69.0% (29/42, 54.0~80.9%), 주인공 27/30. 같은 41건에서 본문+LLM 방식(11/05 기준선)은 P 94.1% (32/34), R 76.2% (32/42) → **정확도는 비슷하고 놓침이 3개 늘어남** (신뢰구간이 겹쳐 통계적으로 구별 안 됨). 규칙 일부(마침표 경계, 그룹 이름 범위, 손보 별칭)는 이 정답지의 놓침을 보고 고쳤으므로 개발용 숫자 (봉인 시험은 평가 단계에서)
- **비용:** 금지 언론사 기사는 LLM 0회 (실시간 RSS 의 약 51%)
- **검토한 대안:** 세 곳을 수집에서 빼기(실시간 뉴스가 절반으로), 지금처럼 본문 요약 유지(언론사 고지와 정면 충돌, 발표·면접에서 방어 불가)
