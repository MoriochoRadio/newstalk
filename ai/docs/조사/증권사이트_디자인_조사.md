# 증권·주식 사이트 디자인 조사 (2026-11-12)

프론트 디자인을 새로 하기 전에 국내외 증권 서비스가 뉴스·종목 화면을 어떻게 보여 주는지 찾아본 기록.
조사 방법: 웹 검색 (2026-11-12). 블로그·에이전시 글이 많아서 "참고 의견" 수준으로 본다.

## 1. 서비스별로 본 것

### 토스증권
- 원칙: 한 화면에서 사용자가 내릴 판단을 하나로 줄인다 ("한 화면 한 기능").
  - 근거: [디지털 인사이트, 토스 10년](https://ditoday.com/%ed%86%a0%ec%8a%a4-10%eb%85%84-%ec%89%ac%ec%9a%b4-%ea%b8%88%ec%9c%b5%ec%9d%b4-%eb%a7%8c%eb%93%a0-%ed%98%81%ec%8b%a0%ea%b3%bc-%ea%b7%b8%eb%8a%98/), [요즘IT](https://yozm.wishket.com/magazine/detail/919/)
- 말투: "~해요" 체로 통일한 쉬운 말투가 금융 앱의 기본 문법이 됐다는 평가.
  - 근거: [디지털 인사이트](https://ditoday.com/?p=151644)
- AI 시그널 (2025-11): 뉴스·공시 중 시장에 영향을 준 것을 골라 "주가가 움직인 이유"를 요약한다. 평소의 흔한 등락에는 돌지 않고, 3개월 평균 대비 의미 있게 움직였을 때(Z-score)만 분석한다.
  - 근거: [헤럴드경제](https://www.heraldk.com/article/2025111117325540433)
- 실시간 이슈 (2026-03): 시장 영향이 큰 이슈 20개를 뽑아 관련 기업과 함께 보여 준다.
  - 근거: [아시아경제](https://core.asiae.co.kr/article/2026032509250465707)
- 비판:
  - AI가 제시한 원인이 정답이라는 보장이 없다. 실적 발표가 있었다는 사실과 그 발표가 주가를 올렸다는 주장은 별개다.
    - 근거: [바이라인네트워크](https://byline.network/2025/12/1217-3/)
  - 너무 쉽게 만들면 위험이 가려진다. '외상' 용어는 금감원 지적 후 '미수거래'로 되돌렸다.
    - 근거: [디지털 인사이트](https://ditoday.com/%eb%af%b8%ec%88%98%ea%b1%b0%eb%9e%98%eb%8a%94-%ec%99%b8%ec%83%81-%ec%98%b5%ec%85%98%ed%88%ac%ec%9e%90%eb%8a%94-%ed%99%80%ec%a7%9d-%ea%b2%8c%ec%9e%84%ed%86%a0%ec%8a%a4%ec%9d%98/)

### 네이버페이 증권
- 종목토론방에 '종목 소식' 계정을 두고, 주가 변동·공시·리포트를 알린다 (2025-07).
  - 근거: [이코노미스트](https://economist.co.kr/article/view/ecn202507040045)
- 종목 상세 화면 맨 위에는 시세(KRX·NXT)를 둔다.
  - 근거: [네이버 보도자료](https://navercorp.com/media/pressReleasesDetail?seq=32071)

### Yahoo Finance (2023-11 개편)
- 종목 화면을 "필요한 데이터를 바로 찾도록" 다시 정리했고, 광고를 40% 넘게 줄였다.
  - 근거: [Yahoo 보도자료](https://unified.www.yahooinc.com/press/yahoo-finance-debuts-new-design-and-features-to-empower-everyday-investors)
- 기사 제목마다 긍정·부정 감성을 표시한다 (Source Sentiment).
  - 근거: [MarketBeat](https://www.marketbeat.com/stocks/NASDAQ/HOOD/news)
- 개편에 반발한 사용자도 있었다 (예전 화면을 되돌려 달라는 청원).
  - 근거: [Change.org](https://www.change.org/p/reinstate-yahoo-finance-classic-and-scrap-the-new-layout)

### Robinhood
- 종목 화면은 차트가 위에 있고, 뉴스는 그 아래 별도 칸에 둔다. "모두 보기"를 누르면 목록이 펼쳐진다.
  - 근거: [Robinhood 도움말](https://robinhood.com/us/en/support/articles/viewing-stock-detail-pages)

### Koyfin
- 사용자가 직접 뉴스 화면을 만들고 걸러 보는 방식이다 (전문가용).
  - 근거: [Koyfin](https://koyfin.com/data-coverage/news)

## 2. 디자인 일반 원칙 (실무 글 모음)
- 가장 중요한 정보가 먼저 눈에 들어오게 순서를 잡는다. 모든 것을 한 번에 보여 주지 않는다.
  - 근거: [aufaitux](https://www.aufaitux.com/blog/good-dashboard-design/), [phenomenonstudio](https://phenomenonstudio.com/article/why-your-dashboard-looks-busy-and-your-users-feel-lost/)
- 관심종목에 맞춘 뉴스는 사용자가 기본으로 기대하는 기능이다.
  - 근거: [dev.to](https://dev.to/prateekshaweb/ux-features-clients-expect-in-a-modern-wealth-management-app-design-implementation-tips-for-2024-n8e)
- 숫자는 크고 또렷하게 쓰고 대비를 충분히 준다. 색만으로 뜻을 전하지 말고 화살표·부호를 함께 쓴다.
  - 근거: [fdcapital](https://www.fdcapital.co.uk/designing-financial-dashboards-clients-actually-understand-a-user-centric-ux-approach/)
- 시세가 늦거나 멈춘 상태를 숨기면 신뢰가 깨진다. 기준 시각과 지연 여부를 보여 준다.
  - 근거: [lollypop](https://lollypop.design/blog/2026/june/trading-app-design/)
- 투자 화면은 불안을 키우지 말고 줄여야 한다.
  - 근거: [lollypop](https://lollypop.design/blog/2026/may/investment-dashboard-ux-design-guide/)
- 사용자 평가로 본 국내 증권 앱 UX 비교 (토스·나무·영웅문 등).
  - 근거: [오픈서베이](https://blog.opensurvey.co.kr/article/ux-finance-app-3/)

## 3. 우리 서비스에 주는 뜻 (목업 v2와 비교)
| 조사에서 본 것 | v2 상태 | 할 일 |
|---|---|---|
| 한 화면 한 판단 | 홈에 카드·목록·관심종목 3덩어리 | 홈은 "오늘 무슨 일" 하나에 집중할지 검토 |
| 기사별 감성 표시 (Yahoo) | 색 띠와 이름표로 표시함 | 유지 |
| AI가 "주가 원인"을 단정하면 위험 (토스 비판) | "주가가 움직인 이유가 아니에요" 문구 있음 | 유지. 원인처럼 읽히는 문구는 피하기 |
| 의미 있는 변동 때만 설명 (토스 Z-score) | 없음 | 종목 요약을 "소식이 많은 날"에만 보여 주기 (LLM 비용도 줄어듦) |
| 시세 기준 시각·지연 표시 | 종목 상세에만 있음 | 홈 카드에도 기준 시각 |
| 색 + 화살표·부호 함께 | 등락률에 ▲▼, + 있음 | 유지 |
| 관심종목 맞춤 뉴스 | "내 관심종목만" 탭 있음 | 유지 |

## 4. 차트 디자인 추가 조사 (2026-11-12, 목업 v4에 반영)
- 선 하나, 기간 시작보다 위면 한 색·아래면 다른 색으로 칠한다 (Robinhood). 국내는 상승 빨강·하락 파랑.
  - 근거: [Robinhood Legend 도움말](https://robinhood.com/us/en/support/articles/widgets-in-robinhood-legend), [키움 차트 도움말](https://download.kiwoom.com/hero4_help_new/0600.htm)
- 어제 종가는 점선으로, 축에 이름표를 붙인다.
  - 근거: [Robinhood 공식 X](https://x.com/RobinhoodApp/status/543907356556279808?lang=en), [OneKey PR #13315](https://github.com/OneKeyHQ/app-monorepo/pull/13315)
- 차트 위를 끌면(스크럽) 큰 가격 숫자가 그 시점 값으로 바뀌고, 손을 떼면 현재가로 돌아온다.
  - 근거: [Robinhood advanced charts](https://robinhood.com/gb/en/support/articles/using-advanced-charts/), [제3자 구현 PR](https://github.com/odia11/social-multi-trading-chain-/pull/86)
- 뉴스 표시는 작은 원을 시간에 붙이고 내용은 마우스를 올리면 보여 준다. 차트 위 설명은 3~5개 이하.
  - 근거: [TradingView Marks 문서](https://www.tradingview.com/charting-library-docs/latest/ui_elements/Marks/), [Datashow 주석 가이드](https://datashow.com/field-guides/chart-design/chart-index/sparkline)
- 캔들 대신 단순한 선 하나로 등락을 보여 주는 것이 토스증권식 쉬운 차트라는 분석.
  - 근거: [브런치 분석 글](https://brunch.co.kr/@lucky771628/6)
- 목록용 작은 차트(스파크라인)는 축 없이 방향만 보여 준다.
  - 근거: [Datashow sparkline](https://datashow.com/field-guides/chart-design/chart-index/sparkline)
