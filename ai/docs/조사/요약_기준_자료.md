# 기사 요약 기준과 검증에 쓸 수 있는 자료

2026-11-06 조사. 목적: OpenAI 기사 요약의 기준과 근거를 만들 때 가져다 쓸 수 있는 것 정리.

- 확인 수준: 웹 검색 요약과 Hugging Face 모델 카드로 확인했다. 논문 원문은 다 읽지 않았으니 인용 전에 원문을 볼 것
- 대부분 영어 데이터 연구다. 우리 기사로 잰 값은 아직 없다

## 우리가 정한 요약 목적과 기준 (2026-11-06 사용자와 정함)

- 목적: 기사를 열지 않고 요약만 읽어도 무슨 일인지 바로 알게
- 가장 나쁜 실수: 숫자·회사가 틀림, 원문의 오타·오류를 그대로 전달, 중심이 아닌 내용이 들어감
- 원문이 앞뒤가 안 맞거나 틀려 보이면 그 부분은 요약에서 뺀다 (확실한 것만 말함)
- 우선순위: 사실 일치 > 중심 내용 > 흐름·문장·길이
- 사람 대조: 지승현 혼자 약 50건

## 1. 요약 기준과 오류 분류

| 자료 | 쓸 내용 | 우리 쓰임 |
|---|---|---|
| [SummEval](https://arxiv.org/pdf/2007.12626) (TACL 2021) | 평가 4축: 사실 일치(consistency), 중요 내용 선택(relevance), 흐름(coherence), 문장 품질(fluency). 전문가 3명 일치도 kappa 0.71 | 요약 기준의 틀. 위 우선순위와 그대로 맞음 |
| [FRANK](https://arxiv.org/pdf/2104.13346) (NAACL 2021) | 사실 오류 6유형: 대상(회사·숫자 속성) 오류, 서술 오류, 시간·장소 오류, 인과 연결 오류, 원문에 없는 내용, 문법 오류 | 사람 대조 시트의 오류 칸. 공시 기간 오독(보락)은 시간 오류 |
| [LongEval](https://arxiv.org/pdf/2301.13298) (EACL 2023) | 요약 전체에 점수를 주기보다 문장 단위로 판정할 때 평가자 일치도가 크게 높음 | 50건을 문장마다 판정 |

## 2. 근거를 붙여 요약하는 방법

| 자료 | 쓸 내용 | 우리 쓰임 |
|---|---|---|
| [sui-1](https://arxiv.org/html/2601.08472v1) (2026) | 원문 문장마다 ID 를 붙이고, 요약에 그 ID 를 인용하게 함. 인용을 검증 | 요약 문장마다 원문 문장 번호를 내게 하고 코드로 확인하는 설계의 근거 |
| [Are Finer Citations Always Better?](https://arxiv.org/pdf/2604.01432) (2026) | 근거 품질은 문장 단위보다 문단 단위에서 가장 좋았음 | 주의점: 문장 번호로 시작하되 앞뒤 문장까지 허용 |
| [근거 기반 생성 조사](https://arxiv.org/pdf/2508.15396) (2025) | 요약 연구 대부분은 문서·문단 단위 근거 | 위와 같은 방향 |
| [SummaC](https://arxiv.org/pdf/2111.09525) (TACL 2022) | 원문과 요약을 문장 단위로 나눠 문장끼리 NLI 로 비교. 균형 정확도 74.4% | 아래 NLI 모델을 쓰는 방식 |

## 3. 자동 검사 도구

| 도구 | 한국어 | 비용 | 판단 |
|---|---|---|---|
| [mDeBERTa 다국어 NLI](https://hf.co/MoritzLaurer/mDeBERTa-v3-base-xnli-multilingual-nli-2mil7) (MIT, 2.8억 파라미터) | 지원 | 무료, PC 실행 | **1순위.** 요약 문장이 원문 문장에서 나오는지 판정. 결과가 매번 같고 기사를 밖으로 안 보냄. 우리 기사로 정확도부터 잴 것 |
| 코드 대조 | - | 무료 | 숫자·단위·회사명·연도를 원문과 대조. 이미 `step8_daily.py` 에 숫자 검사가 있음 |
| [Vectara HHEM](https://hf.co/vectara/hallucination_evaluation_model) | 공개판은 영어만, [한국어는 유료 API](https://www.vectara.com/blog/hhem-expanded-language-support) | 유료 | 보류. 비용과 외부 전송 |
| [MiniCheck](https://hf.co/lytang/MiniCheck-Flan-T5-Large), [AlignScore](https://arxiv.org/abs/2305.16739) | 영어 위주 | 무료 | 제외 |
| FreeLLMAPI (여러 무료 LLM 묶음, [레포](https://github.com/tashfeenahmed/freellmapi)) | 모델마다 다름 | 무료 한도 | 요약 생성에는 안 씀: `auto` 는 모델이 바뀌어 재현 불가, 무료 티어 일부는 입력을 학습에 씀, 한도에 자주 걸림. 사람 50건 비교용 판정자로만, 모델 하나 고정해서 소량 |

주의: [K-HALU](https://proceedings.iclr.cc/paper_files/paper/2025/hash/cfcadfe84ee49908cde1fc2992c38d20-Abstract-Conference.html) (ICLR 2025) 에서 공개 모델은 한국어 환각 탐지에서 유료 API 보다 크게 뒤처졌다. 공개 NLI 모델은 사람 50건으로 정확도를 재기 전에는 믿지 않는다.

## 6. 쓰지 않을 것과 이유

- **요약 모델 교체**: [KoBART 요약](https://hf.co/gogamza/kobart-summarization), [T5 한국어 요약](https://hf.co/eenzeenee/t5-base-korean-summarization), [Granite 2B 요약판](https://hf.co/mindw96/granite-3.1-2b-instruct-korean-summarization) 은 근거 표시가 없고 지금 LLM 보다 낫다는 근거가 없다
- **한국어 금융 LLM**: [₩on](https://arxiv.org/html/2503.17963v1), [KFinEval](https://arxiv.org/html/2504.13216v1) 은 금융 지식 문제 풀이용이고 요약 평가가 없다
- **찾지 못한 것**: 한국어 경제 기사를 근거와 함께 요약하는 완성 모델, 한국어 요약 충실도 벤치마크, 국내 언론의 요약 전용 기준
