## 1. 차단기가 "시험 중"으로 굳음

**어떻게 동작하나** (`core/resilience.py`)
- 실패가 쌓이면 쉼(open) → 쉬는 시간이 지나면 `allow()` 가 **1번만** 허용하고 `probing=True` 로 표시 (97~113줄)
- 그 1번의 결과로 `success()`(닫힘) 또는 `failure()`(다시 쉼)를 불러야 `probing` 이 풀림
- `probing` 이 남아 있으면 `allow()` 는 시간이 지나도 계속 False (105줄 `or s.get("probing")`)

**문제: 허용받고 결과를 안 남기는 길**

| 위치 | 언제 | 결과 |
|---|---|---|
| `steps/dart.py` `summarize_disclosures` 256줄 | 한 실행 안에서 공시 수집(126줄, 앞쪽)과 공시 요약(뒤쪽) 사이에 쉬는 시간이 끝나면 시험 1번을 요약이 가져감. 요약은 `breaker.success/failure` 를 안 부름 | **DART 공시 수집·요약 둘 다 멈춤** |
| `steps/step4_body.py` 171줄 | 시험으로 뽑힌 기사가 한경 유료 기사(`PAYWALL`) → `continue` | 그 사이트 본문 받기 멈춤 (한경 기사 약 1/3 이 유료) |
| `steps/step4_body.py` 164~169줄 | 시험 기사에 AI 금지 고지 | 같음 |
| `steps/step4_body.py` 151~155줄 | 사이트 전체 AI 거부 표시 (요청 전 `continue`) | 같음 (이 경우는 언론사가 제목만으로 바뀌어 영향 작음) |

**재현** (DB 없이, `ai` 폴더에서)
```python
import tempfile, pathlib
from hk_llm.core.resilience import Breaker
b = Breaker(pathlib.Path(tempfile.mkdtemp()) / "s.json")
b.failure("DART", "점검(800)", now=1000, immediate=True)   # 10분 쉼
b.allow("DART", now=1590)    # False (공시 수집 시점, 아직 쉬는 중)
b.allow("DART", now=1610)    # True  (공시 요약 시점, 시험 1번) → 결과 안 남김
b.allow("DART", now=1610 + 600 * 60)   # 600분 뒤에도 False
```
지금 푸는 법: `python -m hk_llm.core.resilience close DART` (사이트면 `close www.hankyung.com`)

**고칠 방향 (고르기)**
- A. 결과를 반드시 남기기: `step4` 의 유료·고지 `continue` 앞에 `breaker.success(host)` (페이지는 정상으로 왔으니 사이트 문제 아님). `summarize_disclosures` 는 원문 받기 성공/실패를 `breaker.success("DART")` / `record_dart_failure(e)` 로 기록
- B. `summarize_disclosures` 는 시험을 가져가지 않게: `allow()` 대신 "지금 쉬는 중인가"만 보는 함수(예: `is_open`)를 새로 써서 읽기만
- C. 안전장치: `probing` 이 일정 시간(예: 15분) 넘게 남아 있으면 `allow()` 가 다시 시험을 허용 (위 길을 놓쳐도 스스로 풀림)
- 추천: A + C (C 는 앞으로 새 길이 생겨도 막아 줌)

**확인 시험** (`tests/test_resilience.py` 에 추가)
- 시험을 받고 결과 없이 넘어가도 15분 뒤엔 다시 허용 (C)
- `step4`: 유료 기사가 시험으로 뽑혀도 다음 기사는 요청함
- `summarize_disclosures`: 쉬는 중에 끝난 시점이 와도 `collect_disclosures` 다음 실행이 DART 를 다시 부름

## 2. 언론사 방침 자동 바꿈 → 지난 요약 전부 삭제

**지우는 동작 (확인함)**
- `steps/title_only.py` `purge_ai_results` 81~89줄: "제목만" 언론사의 RSS 기사 **전체**(날짜 제한 없음)에서 `body·summary·keywords·sentiment·companies·model` 을 NULL, 상태를 `LISTED` 로
- 매 실행 `link_title_only` 96줄이 부름 → 방침이 바뀐 다음 실행에서 바로 지워짐
- 사람이 `press_policy reset` 으로 되돌려도 요약은 **어제 이후만** 다시 함 (`step5` since) → 지난 요약은 복구 안 됨, 다시 하면 OpenAI 비용

**자동으로 바뀌는 조건** (`core/press_policy.py`, `steps/rights.py`)
- 기사 페이지 HTML **전체**에서 `NOTICE`(rights.py 40줄: ⓒ·저작권자·무단 전재 뒤 60자 안 "AI 학습/활용 … 금지")를 찾음
- 서로 다른 기사 2건(`PAGE_HITS`, press_policy.py 37줄)이면 그 언론사 전체를 `TITLE_ONLY` 로 (84줄)
- 사이트 robots.txt `Content-Signal: ai-input=no`·`tdmrep.json` 이면 1번에

**걱정되는 경우 (확인 필요)**
- 한경·파이낸셜뉴스·전자신문 페이지에 **연합뉴스 기사를 받아 실은 글**이나 연합 기사 꼬리(`<저작권자(c) 연합뉴스, … AI 학습 및 활용 금지>`)가 있으면 → 하루 2건만 걸려도 그 언론사 전체가 "제목만" → 지난 요약 전부 삭제
- 본문이 아니라 페이지 전체를 보므로 추천·관련 기사 영역에 걸려도 같음

**확인 방법**
- 내 PC DB 에서 `SELECT press, url FROM article WHERE channel='RSS' AND press IN ('한국경제','파이낸셜뉴스','전자신문') AND (title LIKE '%연합%' OR description LIKE '%연합뉴스%') LIMIT 20` → 그 주소를 브라우저로 열어 기사 끝에 연합 고지가 있는지
- `python -m hk_llm.steps.rights` (지금 상태 확인, 언론사마다 기사 1건)
- `hk_llm/logs/press_override.json` 에 `hits` 가 쌓이는지

**고칠 방향**
- 지우기를 되돌릴 수 있게: 자동으로 바뀐 경우엔 지난 기사 AI 결과를 지우지 말고 **새 기사부터만** 제목만 처리 (지우기는 사람이 확인한 뒤 명령으로). 또는 지우기 전 백업 테이블에 복사
- 오탐 줄이기: 고지를 **본문 영역**(step4 `BODY_XPATH` 로 뽑은 본문 끝)에서만 찾기, 기사 출처가 그 언론사 자신일 때만(연합 받아쓰기 기사는 그 기사만 건너뜀)
- 자동 바꿈은 지우기 없이 Slack 알림만 하고, 사람이 확인 후 `press_policy exclude/title-only` 로 확정하는 것도 방법
