## 1. 검수자 1(`지승현`) 50건 집계 결과

### 1.1 구성 및 대표 지표 원칙
- **전체 50건**:
  - `blind` (20건): AI 답을 가린 채 본문에 등장하는 상장사 후보 체크박스에서 직접 선택 (사람 라벨: 단일 종목 10건, 복수 종목 4건, 연결 없음 6건)
  - `review` (30건): AI가 실제로 연결한 종목(30개)의 맞음(`O`)/틀림(`X`) 판정 + 빠진 종목 직접 입력 (함정 문항 `-t` 5건 포함)
- **대표 지표 원칙 및 `blind` 20건 3회 재실행 실측**:
  - `review` 30건은 AI 답을 먼저 보여 주므로 확증 편향(Confirmation Bias)이 섞인다.
  - `blind` 20건은 [`정답지확인.html`](../../../data/eval/정답지확인.html)의 `DATA.llm`에 당시 AI 답이 빠져 있어, 초기 역산값은 폐기하고 **HTML 문장(`sentences[1:]`, 제목 중복인 `sentences[0]` 제외)을 입력으로 [`step5_summary.py`](../../hk_llm/steps/step5_summary.py) + [`step6_match.py`](../../hk_llm/steps/step6_match.py)를 3회 재실행(총 60회 호출, \$0.0396, DB 미저장, 결과 파일 [`data/eval/blind_20_llm_runs.json`](../../../data/eval/blind_20_llm_runs.json))해 실제 AI 출력과 실행 간 흔들림을 측정**했다.
  - 단, 재실행 값은 **라벨 생성 당시 DB의 원본 `body`가 아니라 HTML의 문장 배열을 이어 붙인 입력 조건**이라는 점을 함께 명시한다.
  - 기준 위반을 고치는 보정(Adjudication)은 AI 답을 모르는 제3자가 수행해야 하며, 제3자 최종 판정 전까지는 **"보정 안"**으로 표기하고 **원본(Raw) 수치를 먼저 보고**한다.

#### 수치를 읽을 때 주의할 점 ([`blind_20_llm_runs.json`](../../../data/eval/blind_20_llm_runs.json))
1. **안정적인 것과 맞는 것은 다르다**: 최종 연결 종목은 `19/20`건이 3회 모두 같았지만, LLM이 뽑은 원본 회사 목록(`companies`)은 **`4/20`건에서 흔들렸다**. 특히 `D029`는 LLM이 3개·5개·1개로 다르게 뽑았는데 명단 규칙(`LIST_MAX=5`)이 전부 막아 **세 번 다 똑같이 놓친 경우**다.
2. **감성은 연결보다 덜 안정적이다**: 3회 모두 연결된 14개 종목 중 감성이 3회 모두 같은 경우는 **11/14(78.6%)**이며, 달라진 3개가 모두 복수 종목 기사인 `D076`(`대신증권·미래에셋증권·삼성증권`)에서 나왔다.
3. **복수 종목의 낮은 Recall은 표본·시황 영향이 크다**: 복수 종목 기사가 4건뿐이고, 원본 놓침 18개 중 10개가 시황 기사 `D053`에서 나왔으며 그중 8종목은 정책상 제외 대상이다.
4. **Precision 100%는 단독 인용 금지**: 분모가 14~15개로 작아 95% 신뢰구간이 **약 79~100%**다.
5. **당시 DB 답이 아닌 재실행 값**: 본문을 HTML 문장(`sentences[1:]`)으로 이어 붙인 입력 조건이다. 현재는 규칙을 바꾸지 않아 유효하지만, 이 20건을 보고 규칙을 고치면 개발용(Dev) 표본이 되므로 최종 검증용 기사는 새로 뽑아야 한다.

### 1.3 함정 문항(`-t` 5건) 점검과 `D043-t` 쟁점
- `D051-t` (대상), `D093-t` (대상), `D025-t` (선진), `D037-t` (남성) 4건은 일반단어 오매칭 함정으로 검수자가 모두 `X` 처리했다.
- **`D043-t` (현대자동차) — [판정 필요 / 함정 문항 설계 결함]**:
  - 검수자가 `O`로 표시했다. 원문을 확인하면 단순 오매칭이 아니라 `"현대자동차 합작 공장"` 당사자로 본문에 실제 1회 등장한다.
  - 따라서 검수자의 실수로 단정하거나 보정 안 JSON에서 `O → X`로 바꾸면 안 되며, 제3자 판정 대상이자 함정 문항 설계 결함으로 분류한다.

3. **`D043-t`의 `현대자동차` — [판정 필요]**
   - 본문에 `"현대자동차 합작 공장"` 당사자로 1회 등장하므로 제3자 판정 대상으로 분류한다.

4. **`D080` (`blind`, 3회 중 1회(Run 0)만 놓침 — `한국항공우주`)**
   - 본문 첫 문장에 `"한국항공우주산업(KAI)"`로 병기돼 있다. Run 1·2는 `KAI`로 뽑아 정상 연결됐으나, **Run 0은 `한국항공우주산업(KAI)` 그대로 뽑았고 [`norm()`](../../hk_llm/steps/step6_match.py#L47-L49)이 `(주)`·`(\w{6})`만 지우고 `(KAI)` 같은 괄호 약칭은 지우지 않아 사전 매칭에서 탈락**했다. (단, 60회 재실행과 하루치 182건의 LLM 회사 이름 437개 중 괄호가 든 이름은 13개이고 괄호 제거로 새로 일치하는 것은 이 1건뿐이라 영향 규모는 작다.)

## 2. 왜 "예외 규칙 추가"를 피해야 하나

초기 개선안에서 검토했던 아래 방안들은 코드·데이터 확인 결과 **효과 대비 복잡도(변수 수)만 늘리거나 전제가 틀려 채택하지 않는다.** (측정 표본 조건: 2026-11-05 하루치 기사 182건, 비즈워치·연합인포맥스·전자신문·파이낸셜뉴스 4개 언론사)

| 초기 검토안 | 채택하지 않는 이유 (데이터·코드 확인 결과) |
|---|---|
| **1회 언급 구제 규칙 (조건 3개 추가)**<br>(일반단어 아님 + 수치 동반 + 이유 단어 겹침) | 조건 3개를 새로 추가해 "변수가 너무 많다"는 문제를 악화시킨다. 하루치 182건에서 **명단 판정(`LIST_MAX`)을 걸지 않은 상태**로 적용하면 1회 후보 48개 중 27개가 통과하며 저PBR 명단·시황 기사까지 섞여 들어온다. 먼저 `2회 → 1회` 완화 시 늘어나는 17건을 사람이 판정해 보는 것이 순서다. |
| **사전 필터로 "손실 0% + 비용 50% 절감" 주장** | 182건 중 103건은 "본문에 상장사가 없는 기사"가 아니라 "LLM 답이 사전과 안 맞은 기사"다. 실제 본문(하루치 182건·4개 언론사) 기준으로 **2글자 이상 사전은 30건 제외(16% 절감, 손실 0)**, **3글자 이상은 84건 제외(46% 절감 대신 연결 기사 64건 중 4건 손실)**다. 두 수치를 동시에 달성할 수 없으므로 그림자 측정 후 안전 구간(16%)부터 검토한다. |
| **금액 단위 정규화 (`step5`, `step8`)** | [`step5`](../../hk_llm/steps/step5_summary.py)는 연도만 검사하고 숫자 검사는 [`step8_daily.py`](../../hk_llm/steps/step8_daily.py)에만 있다. 182건 중 걸린 사례가 단 1건뿐이라 복잡한 파서를 추가할 이유가 약하다. |
| **기사 묶기에서 종목명 먼저 제거 (`step7`)** | [`_bigrams()`](../../hk_llm/steps/step7_group.py#L27-L30)가 이미 `t.replace(stock_name, "")`로 종목명을 제거하고 있으며, 본문 0.15 조건은 코드에 없다(제목 0.10만 사용). 현재 묶음은 화면에 노출되지 않으므로 후순위다. |

## 3. 수정된 개선 우선순위

새 변수를 늘리는 대신, **측정 없이 바로 고칠 수 있는 결함(본문 잡음 포함) → 평가 기준 고정 → 불필요한 변수 삭제 → 대안 비교 측정** 순서로 진행한다.

| 순위 | 구분 | 항목 | 대상 파일 | 내용 및 근거 |
|:---:|---|---|---|---|
| **1** | **결함 수정** | 측정 없이 고칠 수 있는 파이프라인·본문 결함 | [`dart.py`](../../hk_llm/steps/dart.py), [`step4_body.py`](../../hk_llm/steps/step4_body.py), [`step5_summary.py`](../../hk_llm/steps/step5_summary.py), [`step6_match.py`](../../hk_llm/steps/step6_match.py), [`sns.py`](../../hk_llm/steps/sns.py), 백엔드 매퍼(`ArticleMapper.xml`, `StockMapper.xml`) | ① 공시 관련도 `1.00` 고정으로 관련도순 상위 100개를 공시가 독점하는 문제 분리 (`dart.py` 및 백엔드 정렬·순위 매퍼)<br>② `ORDER BY article_id DESC`로 특정 언론사가 밀리는 현상 수정 (`step4_body.py`, `step5_summary.py`, `dart.py`)<br>③ 7일 지나 본문 삭제된 기사를 재매칭할 때 `on_topic`을 무조건 통과해 탈락 연결이 되살아나는 버그 차단 (`step6_match.py`)<br>④ 뉴스 처리 전에 SNS가 먼저 돌아 대상 종목이 0개가 되는 실행 순서 수정 (`sns.py`)<br>⑤ **파이낸셜뉴스 본문 하단 `관련종목` 목록 줄 제거**: 파이낸셜뉴스 본문 217건 중 53건(24%)에 사이트의 관련종목 줄이 섞여 언급 횟수·명단 판정에 함께 세어지므로 `step4_body.py` 본문 추출에서 먼저 제거 *(+ 부가: `step6_match.py` `norm()`에서 `한국항공우주산업(KAI)` 같은 괄호 병기 약칭 처리, 전체 437개 중 영향 1건)* |

| **3** | **변수 삭제** | 결과에 영향 없는 죽은 변수 제거 | [`step6_match.py`](../../hk_llm/steps/step6_match.py), 백엔드 Flyway (`match_setting`) | [`score()`](../../hk_llm/steps/step6_match.py#L65-L70)의 주인공 `1.00` / 조연 `0.83`은 DB `min_score(0.70)`를 항상 통과해 연결 결과를 바꾸지 않음. 단, [`relevance()`](../../hk_llm/steps/step6_match.py#L118-L130)가 본문 없는 옛 기사에서 `score`를 쓰고 `match_setting` 테이블은 백엔드 Flyway 소관이므로 **1순위 재매칭 결함 수정 및 팀 합의 뒤에** 연결 점수 변수 4개 제거 (`TYPE_WORDS`, `LIST_TITLED_MAX=9`는 시황 많은 날 측정 후 제거) |
