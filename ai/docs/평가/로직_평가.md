## 1. 결론

1. **구조는 좋다.** 상태값으로 잇는 파이프라인, LLM 후보와 코드 결정의 분리, 근거 문장을 원문에서 고르는 방식, 비용 방어는 유지할 가치가 있다
2. **값은 약하다.** 임계값과 가중치 대부분은 실패 사례로 정했고, 효과 없는 변수도 있다
3. **평가가 가장 약하다.** 사람 라벨은 한 명이 단 50건뿐이고, AI 를 가리고 단 20건은 재실행으로 채점했지만 표본이 작다
4. **규칙을 더 붙이는 개선은 피한다.** 놓침을 줄이려 예외 규칙을 더하면 "변수가 너무 많다" 는 지적이 커진다
