## 배운 것

- **재고 나서 고친다**: "로딩이 길다"를 듣고 처음엔 화면 코드를 의심했지만, 요청마다 시각을 찍어 보니 원인은 백엔드가 KIS 에 한 종목씩 묻는 것. 짐작으로 고쳤으면 엉뚱한 곳을 손댔을 것
- **동시에 해도 한도는 지킬 수 있다**: 나가는 문(줄 서기)을 하나로 두면, 안쪽에서 여러 일꾼이 기다리는 건 괜찮음. Java 21 가상 스레드는 `synchronized` 안에서 잠들면 바닥 스레드를 붙잡아서(pinning) 여기선 보통 스레드
- **압축도 고를 것이 있다**: 실시간(SSE)을 압축하면 이벤트가 모였다가 한꺼번에 가서 "실시간"이 깨짐. 1KB 아래는 압축 비용이 이득보다 큼
- **"원문 그대로"라고 보여 주려면 대조해야 한다**: LLM 이 바꿔 쓴 문장을 인용문처럼 내보내면 거짓말. 검증할 수 있는 것만 보여 줌
- **같은 숫자를 여러 곳에서 세면 한 곳에 모은다**: 파일 두 개 → 상한 두 배. DB 의 한 문장 갱신(`ON DUPLICATE KEY UPDATE`)은 동시에 더해도 빠지지 않음
- **로컬 테스트가 가끔 실패한 이유**: 테스트와 수집기가 같은 실제 DB 를 써서, 테스트가 글 표를 비우는 순간 수집기 저장과 부딪힘(deadlock). CI 는 따로인 DB 라 괜찮음 → 시험용 DB 분리는 할 일로 남김
- **사용자 피드백은 "글자가 많다"가 가장 많았다**: 설명을 늘리는 대신 숫자·색·크기로 말하게(뉴스 지도 칸은 종목 이름 + 한 낱말 + 기사 수). 시간대별 보도량처럼 "투자자가 행동으로 안 옮기는 정보"는 뺌
